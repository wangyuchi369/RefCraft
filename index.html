Benchmark & Evaluation

A task combines a natural-language instruction with screenshots from one to five reference webpages. The agent must selectively interpret and compose visual properties while implementing the requested functionality; reproducing a single screenshot is not the objective.

Dataset Statistics

  • 300tasks
  • 186webpage types
  • 3,491reference screenshots
  • 12,082scored criteria

Evaluating the Complete Task

Models operate in a shared OpenCode environment. Each agent writes a self-contained HTML page and may render, inspect, and revise intermediate implementations. Browser traces and measurements expose relevant page states; programmatic checks assess deterministic criteria, while a vision-language judge evaluates semantic and perceptual requirements.

B

Keypoint completion
Mean normalized score across the task’s keypoints.

C

Core functionality
Minimum completion rate across essential functional goals.

R

Reference following
Mean adherence across applicable reference groups.

1Score each task
St=min⁡(Bt,Ct,Rt)
2Average across tasks
Overall=1300∑t=1300St

Each task is limited by its weakest dimension. Overall averages these task scores; R is omitted when no reference group applies.

How the benchmark is constructed

1. Visual reference pool

Licensed templates, conventional synthetic pages, and atypically styled pages provide varied layouts, palettes, typography, components, interactions, and visual character.

2. Controlled task synthesis

Each design dimension can copy, adapt, or invert a reference, follow an explicit textual requirement (specify), or remain unconstrained (ignore).

3. Verified evaluation keypoints

Requirements are decomposed into independently assessable criteria, checked through model review and revised by ten web-development experts.
